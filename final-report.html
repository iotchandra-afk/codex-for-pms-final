03 / Inspect behavior, not just configuration

The code contains a trap with no timed recovery.

A shorter offer window feeds an existing history penalty. Lower rank can remove the very opportunities needed to earn acceptance credit.

01 / WINDOW

90 → 60 seconds

The same controlled 75-second answer changes from taken to missed.

02 / HISTORY

Miss = refusal

Both subtract 0.12. Taking a callout earns only 0.08.

03 / RANK

Someone else accepts

History still weighs 0.25. Dispatch stops offering after acceptance.

04 / RECOVERY

No offer, no credit

Quiet time alone does not improve a retained score. The aging TODO was never implemented.

Answer to engineering's question: an explicitly declined ping and a missed ping receive the same history treatment in this code. Whether that was intended is a product-policy question, not something the code can authorize.

What we proved

  • 16 controlled tests pass against unchanged routing source.
  • All 1,696 observed outcomes were replayed under three initial-score assumptions; the severe four end at modeled zero.
  • A responder can remain available/listed and still receive no offer when an earlier candidate accepts.

What we did not prove

  • Actual historical scores, answer times, candidate sets or deployed version.
  • That responders were automatically marked unavailable.
  • That restoring 90 seconds restores already lost priority.
  • That every lost offer was caused by this mechanism.

Reweighting reduced each miss's history contribution from 0.048 to 0.030; it did not increase the penalty mathematically. The timeout change and older recovery gap are distinct. Mechanism, source map and limits · Test evidence.
